# 可配置应用运行框架

## 接入模块

每个可热替换组件实现 `Module`：

1. `Name` 返回唯一模块名，`Dependencies` 声明依赖模块。
2. `Validate` 只检查配置，不创建外部资源。
3. `Prepare` 按依赖顺序创建新资源，失败会按反序关闭本次已经创建的资源。
4. 资源实现 `Resource.Close`，关闭顺序始终与依赖启动顺序相反。

依赖图按拓扑顺序启动：被依赖者先准备，依赖者后准备；关闭时反向执行。

## 发布和恢复

- 首次启动调用 `Start`，配置只有在全部模块校验和准备成功后才进入发布；配置文件通过临时文件原子替换，随后立即切换活动版本。
- 已启动后再次调用 `Start` 返回 `runtime already started`，不会改写持久化配置。
- 后续发布调用 `Reload`；校验、准备、落盘或状态切换失败都保留当前活动版本和磁盘上的上一份成功配置。
- 成功 `Reload` 后，新版本立即对新租约可见；旧版本资源等待所有在途租约 `Release` 后关闭。
- 进程重启时调用 `Open`，只会恢复最近一次真正发布成功的配置并重新准备资源。

## 使用租约

执行业务操作时通过 `Lease` 固定一个完整配置版本：

```go
lease, err := manager.Lease()
if err != nil {
    return err
}
defer lease.Release()

db := lease.Resource("db")
cfg := lease.Config("db")
```

不要把 `lease.Resource` 返回的资源保存到租约生命周期之外。重配置可能已经让该资源等待关闭；租约释放后，框架才会关闭旧资源。`Close` 同样会等待活动版本上的全部在途租约结束，然后再关闭资源。

## 候选生命周期

外部使用者可以把准备和发布拆成两步：

```go
candidate, err := manager.Prepare(ctx, newConfig)
if err != nil {
    return err // 已创建的资源在返回前按反序释放，当前服务不变
}
// 此时候选只是"准备完成"：不会出现在活动版本里，也不会落盘。
if err := candidate.Publish(ctx); err != nil { /* ... */ }
```

- `Prepare` 只做校验、建资源，并把候选钉在创建时的活动版本（基线版本）上；准备成功绝不等于生效。
- `Candidate.Publish` 先原子落盘再切换活动版本；`Candidate.Abandon` 释放候选全部资源，幂等且不影响活动版本。
- 多个候选基于同一旧版时，先发布一份后活动版本前移；另一份再发布会得到 `ErrBaselineChanged`，不会覆盖更新。冲突候选的资源仍然保留，调用方核对基线后必须放弃并基于新版本重新准备。
- `Manager.Rollback(ctx, revision)` 取历史发布中的配置重新准备并发布，是一次真实切换（占用新版本号）；历史中不存在的版本返回 `ErrRevisionMissing`。
- `Start`/`Reload` 是"准备后立即发布"的便捷封装；发布失败会自动放弃本次候选。

## 可查询视图

- `Candidates` 返回尚未发布、也未放弃的候选（含基线版本与配置）。已发布、已放弃、准备失败或进程重开都不会泄漏候选。
- `ActiveConfig` 返回当前真正生效的配置。
- `History` 返回每次真正成为活动版本的发布记录（回退也占一条新版本）。
- `Attempts` 是对照记录：每次实际切换（`Switched=true`）以及所有未生效的尝试（准备失败、基线冲突、落盘失败、主动放弃等）都各有一条。

## 失败语义

- 校验失败不会调用任何 `Prepare`。
- 准备失败只关闭本候选已经创建的资源，不影响当前版本。
- 候选被放弃或发布回退时，关闭操作幂等，成功关闭过的资源不会再次关闭。
- 准备或启动失败、放弃候选以及进程重开，都会释放/清空本次候选资源，不向候选列表和磁盘泄漏。
- 重复启动、准备失败、上下文取消和管理器关闭都不会用失败配置覆盖磁盘。
- 只有完成资源准备、原子配置落盘和活动版本切换的配置，才可在下次启动时恢复。
